# 政策知识库 · 生产部署手册

> 目标：把 `feishu-webapp` 部署到自己的服务器，用 HTTPS 域名对外提供服务，
> 用户在**飞书工作台**点应用图标即可免登使用。
>
> 全程约 40 分钟（不含域名备案与飞书审批等待）。
> 已有的 `docs/上线部署清单.md` 是勾选清单，本手册是它的操作展开版。

---

## 0. 先认清架构：飞书只做「入口 + 登录」

```
用户在飞书工作台点图标
        │
        ▼
浏览器 / 飞书内嵌容器 打开 https://policy.你的域名.com
        │
        ├─ 有会话 Cookie ─────────────► 直接进应用
        │
        └─ 无 Cookie → 302 跳 open.feishu.cn 授权
                            │（飞书已登录则静默通过，不弹扫码）
                            ▼
                   /auth/callback?code=xxx
                            │ 服务端用 code 换 user_access_token
                            ▼
                   AES-256-GCM 加密写 HttpOnly Cookie
                            │
                            ▼
              ┌─────────────────────────────┐
              │  policy-api/src/server.js   │  ← 唯一进程，单端口
              │  · OAuth 登录               │
              │  · 10 张表只读（Bitable）    │
              │  · 审核/订阅/采集写链路      │
              │  · 自建前端托管（/ + /admin/）│
              └──────────┬──────────────────┘
                         │ tenant_access_token
                         ▼
              飞书多维表格（10 张专题表）
```

**关键认知**：业务代码、数据库、外部网络请求**全部在你自己的服务器上**，
飞书不限制你的出网。之前本地「点按钮爬不到」是 WorkBuddy 沙箱的问题，
部署到正常服务器后按钮会自己真爬。

## 1. 准备服务器与域名

### 1.1 服务器

| 方案 | 配置 | 说明 |
|---|---|---|
| 轻量应用服务器 ⭐ | 2 核 2G / 40G SSD / 3-5M 带宽 | 够用，几十元/月 |
| CVM | 2 核 4G 起 | 要进 VPC 打通内网时选 |

系统选 **Ubuntu 22.04 LTS**（本文命令以此为准）。

**必须开放的安全组端口**：`22`（SSH）、`80`（HTTP，证书签发与跳转）、`443`（HTTPS）。
`3000` **不要**对外放行——它由 Nginx 在本机反代。

### 1.2 域名

需要一个域名（如 `policy.example.com`），A 记录指向服务器公网 IP。

> 国内服务器需备案才能用 443。不想备案可以用境外服务器 + 免备案域名。

### 1.3 记下公网出口 IP

```bash
curl ifconfig.me
```

这个 IP 后面要填进**飞书后台的 IP 白名单**，漏配会导致 10 张表全部 403。

## 3. 部署代码

### 3.1 放代码

```bash
sudo mkdir -p /opt/policy-kb
sudo chown -R $USER:$USER /opt/policy-kb
# 方式一：有 git 仓库
git clone <你的仓库> /opt/policy-kb
# 方式二：本地 rsync 上去
rsync -avz --exclude node_modules --exclude data ./ username@服务器IP:/opt/policy-kb/
```

### 3.2 前端（随包自带，无需单独拷贝）

前端已随代码包托管在 `policy-api/public/`：`index.html`（总览首页）+ `app/`（首页资源）+ `admin/`（审批工作台），全部自持源码，不再依赖任何平台构建产物。

```bash
# 服务器上确认三样都在即可
ls /opt/policy-kb/policy-api/public/index.html
ls /opt/policy-kb/policy-api/public/app/app.js
ls /opt/policy-kb/policy-api/public/admin/index.html
```

> 想改首页/审批台界面，直接编辑上述文件后重启服务即生效（无前端构建步骤）。

### 3.3 配环境变量

```bash
cd /opt/policy-kb
cp .env.production.example .env
chmod 600 .env          # 含密钥，禁止其他用户读
vim .env
```

必填项：

```ini
FEISHU_APP_ID=cli_xxxxxxxxxxxxxxxx
FEISHU_APP_SECRET=xxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxx
FEISHU_REDIRECT_URI=https://policy.example.com/auth/callback
SESSION_SECRET=<openssl rand -hex 32 的输出>
NODE_ENV=production
PORT=3000
CRON_ENABLED=true
CRON_HOUR=8
CRON_MINUTE=0
```

生成密钥：

```bash
openssl rand -hex 32
```

> **不要**在 `.env` 里保留 `MOCK_LOGIN=true`。生产环境一旦检测到它，
> 服务会直接拒绝启动。

可选（推荐）：让页面「采集并比对」与「AI 提取」也走真大模型

```ini
# 配了之后：按钮采集 → AI 精提取补全文号/机关/生效日期/金额/省份；
#           比对 → AI 语义查重（识别标题不同但实为同一政策），并输出匹配原因；
#           待确认条目的「AI 提取」→ 大模型给出字段建议。
# 不配则自动回落本地正则规则，功能不受影响。任意 OpenAI 兼容服务均可
# （DeepSeek / Kimi / 智谱 / 通义 / vLLM…）。
LLM_BASE_URL=https://api.deepseek.com/v1
LLM_API_KEY=sk-xxxxxxxxxxxxxxxx
LLM_MODEL=deepseek-chat
```

> 设计约束：大模型只负责「填空补全 + 建议」，关键金额/日期字段仍需人工在
> 「核对并确认入库」步骤核对后才会写入，不会自动入库。

### 3.4 装依赖

```bash
cd /opt/policy-kb
npm install --omit=dev --no-audit --no-fund
```

### 3.5 选一种方式托管进程

#### A. systemd（推荐）

```bash
sudo useradd -r -s /usr/sbin/nologin www-data 2>/dev/null || true
sudo chown -R www-data:www-data /opt/policy-kb/data 2>/dev/null || true
sudo cp deploy/systemd/policy-kb.service /etc/systemd/system/
sudo sed -i 's#/opt/policy-kb#/opt/policy-kb#g' /etc/systemd/system/policy-kb.service
sudo systemctl daemon-reload
sudo systemctl enable --now policy-kb
sudo systemctl status policy-kb
```

#### B. Docker

```bash
docker compose -f deploy/docker-compose.yml up -d --build
docker compose -f deploy/docker-compose.yml ps      # 看 healthy
```

> 数据卷 `app-data` 持久化了 `data/db.json`，容器重建数据不丢。

#### C. pm2

```bash
sudo npm i -g pm2
sudo mkdir -p /var/log/policy-kb && sudo chown $USER /var/log/policy-kb
pm2 start deploy/ecosystem.config.js --env production
pm2 save && pm2 startup
```

验证进程活着：

```bash
curl http://127.0.0.1:3000/healthz
# {"ok":true,"ts":...}
```

## 4. Nginx + HTTPS

### 4.1 先签发证书

```bash
sudo mkdir -p /var/www/html
sudo certbot certonly --webroot -w /var/www/html -d policy.example.com
```

### 4.2 部署反代配置

```bash
sudo cp deploy/nginx/policy-kb.conf /etc/nginx/conf.d/policy-kb.conf
sudo sed -i 's/policy.yourdomain.com/policy.example.com/g' /etc/nginx/conf.d/policy-kb.conf
sudo nginx -t && sudo systemctl reload nginx
```

配置里已经处理好的三个坑：

| 坑 | 配置里的处理 |
|---|---|
| OAuth 回调地址拼错（拿到 `http://` 导致登录失败） | 透传 `X-Forwarded-Proto $scheme` |
| 飞书内嵌容器里打开白屏 | 用 CSP `frame-ancestors` 放行飞书域，**不设** `X-Frame-Options: DENY` |
| 内嵌场景下会话 Cookie 被浏览器丢弃 | 服务端已按生产环境自动 `SameSite=None; Secure`，必须走 HTTPS |

### 4.3 证书自动续期

```bash
sudo certbot renew --dry-run      # 先演练
sudo systemctl enable --now certbot.timer
```

## 5. 飞书开放平台配置

打开 <https://open.feishu.cn/app> → 你的企业自建应用。

| # | 位置 | 填什么 |
|---|---|---|
| 1 | 凭证与基础信息 | 记下 **App ID / App Secret** → 填进 `.env` |
| 2 | 应用能力 → **添加「网页应用」** | PC 端主页 / 移动端主页都填 `https://policy.example.com` |
| 3 | 安全设置 → **重定向 URL** | `https://policy.example.com/auth/callback`（与 `FEISHU_REDIRECT_URI` 逐字符一致） |
| 4 | 安全设置 → **IP 白名单** | 填第 1.3 步拿到的服务器公网 IP |
| 5 | 权限管理 | 开通 `bitable:app`（多维表格）、获取登录用户信息 |
| 6 | **Base 文档应用授权** | 打开政策知识库多维表格 → 右上「…」→ 更多 → 添加文档应用 → 搜本应用 → 授予**可编辑** |
| 7 | 版本管理与发布 | 创建版本 → 申请发布 → 管理员审批 → 设置可用范围 |

> **第 6 步是最容易漏的一步**，也是「确认入库」只能进待同步队列、不能真实写入的根因。
> 未授权时的表现很隐蔽：读接口全部正常，只有写操作静默降级。

## 6. 上线自检

```bash
cd /opt/policy-kb
node scripts/preflight.js
```

它会依次体检并给出可执行的修复建议：

1. 环境变量完整性 / 密钥强度 / MOCK 是否泄漏
2. OAuth 回调地址格式
3. `data/` 可写、`db.json` 可解析、`syncOutbox` 是否积压
4. 自建前端是否就位（`policy-api/public/index.html` + `admin/`）
5. tenant_access_token 能否获取（顺带验证 IP 白名单）
6. **10 张专题表逐一读权限**
7. **写权限探测**：在第一张表建一条记录再删掉（加 `--no-write-test` 可跳过）
8. 线上 `/healthz`、`/api/me`、`/` 三个端点探活

最后输出一份脚本无法自动校验的人工核对清单。退出码 `0` 才建议上线。

> `deploy/deploy.sh` 会在重启前自动跑 `preflight --local`，
> 预检不通过就中止，不会把服务停在半死不活的状态。

## 7. 验收

### 7.1 浏览器直接访问

```
https://policy.example.com
```

- 未登录 → 自动跳飞书授权页 → 扫码 → 回到首页，**右上角显示真实姓名**
- `https://policy.example.com/api/dashboard/stats` → 返回 `source=bitable`、真实条数
- 采集比对页点「确认入库」→ 提示**真实写入成功**（而非「已加入待同步队列」）

### 7.2 飞书工作台（这才是最终形态）

飞书客户端 → 工作台 → 找到应用 → 点击图标：

- **不应再弹扫码**（飞书内已登录，授权静默通过）
- 直接进入首页，数据是真实的
- 若仍跳扫码 → 检查第 6 步的可用范围是否包含当前用户

## 8. 运维

### 8.1 每日备份 db.json

```bash
sudo mkdir -p /var/backups/policy-kb /var/log/policy-kb
echo '15 3 * * * root APP_DIR=/opt/policy-kb /opt/policy-kb/deploy/backup-db.sh >> /var/log/policy-kb/backup.log 2>&1' \
  | sudo tee /etc/cron.d/policy-kb-backup
```

> `db.json` 存着审核单、订阅、采集队列，以及**写权限失效时暂存的待同步操作**。
> 丢了就是用户数据凭空消失，且飞书侧找不回来。

### 8.2 日常更新

```bash
cd /opt/policy-kb
sudo APP_DIR=/opt/policy-kb ./deploy/deploy.sh
```

流程：备份 db.json → 拉代码 → 装依赖 → 校验前端随包 → 预检 → 重启 → 健康探测（30 秒超时即失败告警）。前端改动随 git/rsync 一起进，无需额外产物变量。

### 8.3 看日志

```bash
# systemd
sudo journalctl -u policy-kb -f
# Docker
docker compose -f deploy/docker-compose.yml logs -f app
# pm2
pm2 logs policy-kb
```

### 8.4 巡检节奏

| 频率 | 动作 |
|---|---|
| 每日 | `/healthz` 拨测 + db.json 备份（已自动化） |
| 每周 | `npm run quality`，对比上周 `docs/data-quality/raw.json` 的新增问题行 |
| 每月 | 查 `db.json` 的 `syncOutbox` 是否积压（积压 = 表格写权限又失效） |

## 9. 故障速查

| 症状 | 原因 | 解法 |
|---|---|---|
| 「请求非法，请联系应用开发者」 | 重定向 URL 未登记或与 `FEISHU_REDIRECT_URI` 不一致 | 逐字符比对，含协议、路径、结尾斜杠 |
| 4401 该应用暂不可用 | 未发布 / 未审批 / 用户不在可用范围 | 版本管理与发布 → 补发布并加可用范围 |
| 登录后立刻掉线，反复跳登录 | 内嵌场景 Cookie 被丢弃，或 `X-Forwarded-Proto` 未透传 | 确认 HTTPS + Nginx 透传该头；服务端生产环境自动用 `SameSite=None` |
| 页面空白但接口 200 | 10 张表全部 403 | 飞书后台 IP 白名单漏配服务器出口 IP |
| 读正常，但「确认入库」只提示待同步 | Base 未把应用加为**可编辑**文档应用 | 见第 5 步第 6 项；授权后调 `POST /api/bitable/sync-out` 补推 |
| 证书签发失败 | 80 端口被占或 DNS 未生效 | `curl -I http://域名/.well-known/acme-challenge/test` 排查 |
| 服务起不来，日志提示 MOCK_LOGIN | 生产环境检测到 MOCK_LOGIN | 从 `.env` 删除该行 |
| 改了前端没生效 | 浏览器缓存了旧页面，或 `policy-api/public/` 改动未部署 | 首页外壳是 `no-cache`，强刷即可；静态资源缓存 1h；确认改动已随代码包同步 |

## 10. 文件索引

| 文件 | 用途 |
|---|---|
| `policy-api/src/server.js` | **唯一运行入口**（OAuth + 只读 + 写链路 + 自建前端托管） |
| `Dockerfile` / `.dockerignore` | 镜像构建 |
| `deploy/docker-compose.yml` | 容器编排（含数据卷与健康检查） |
| `deploy/systemd/policy-kb.service` | systemd 单元（裸机推荐） |
| `deploy/ecosystem.config.js` | pm2 配置（备选） |
| `deploy/nginx/policy-kb.conf` | Nginx 反代 + HTTPS |
| `deploy/deploy.sh` | 一键更新部署 |
| `deploy/backup-db.sh` | db.json 每日快照 |
| `scripts/preflight.js` | **部署自检**（上线前必跑） |
| `scripts/scan-quality.js` | 数据质量体检 |
| `.env.production.example` | 生产环境变量样例 |
| `data/db.json` | 本地数据（必须持久化 + 备份） |

> 关于 SCF 云函数：能用但不推荐（出口 IP 随机且同地域共享、无本地磁盘、
> 冷启动慢）。如确需使用见 `deploy/SCF-部署指南.md`。
