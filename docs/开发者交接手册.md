## 三、⚠️ 必知必会的踩坑记录

### 3.1 db.js 内存快照坑（最高优先级）

**现象**：爬虫跑完一格后，刷新审批台，待审批列表不变。

**根因**：`sweep-crawl.js` 子进程每爬完一格就写 `data/db.json`，但主 server 进程持有的内存快照 `_db` 不会自动更新。

**修复**：`src/db.js` 新增了 `syncIfChanged()` 函数，按磁盘 mtime 检测外部写入：

```javascript
// 凡是读取 crawlQueue / crawlTasks 的新代码，读取前都要先调
const db = require('../../src/db');
db.syncIfChanged();  // ← 这行不能少
const items = db.load().crawlQueue;
```

**已落地位置**：
- `crawl-api.js` 的 `crawlList()` 和 `matrix-status` 两处读取前已加
- `save()` 函数写完文件后会同步更新 `_diskMtime`

**如果你新增读取 crawlQueue/crawlTasks 的代码，必须加这一行。**

---

### 3.2 今日口径双轨制（业务规则）

这是最容易搞混的两个字段，**必须严格区分**：

| 字段 | 口径 | 判定逻辑 |
|------|------|----------|
| `todayAdded` | **发布日期**是今天 | `normalizePublishedDate(releaseDate) === today` |
| `addedToday` | **入池日期**是今天 | `shanghaiDate(createdAt) === today` |

**示例**：
- 今天爬到一条政策，但发布日是去年 → 计入 `crawlQueue`，`addedToday=true`，**不**计入 `todayAdded`
- 这条逻辑在 `crawl-api.js` 第 605 行和 673 行已实现

**前端表现**：
- `addedToday=true` 的条目会显示红色 **NEW** 徽标
- 顶部统计栏显示的是 `todayAdded`（按发布日期）

**如果你要改统计口径，记住：两个字段是独立的，不要混用。**

---

### 3.3 待审批列表模式参数

前端调用 `GET /api/crawl/crawled-pending?mode=initial`：

- `mode=initial`：返回**全量**条目，不受今日/历史过滤器影响
- `mode=daily`：只返回今天发布（`releaseDate === 今天`）的条目

**已修复的 bug**：之前默认用 `mode=daily`，导致历史发布但今天才爬到的条目被隐藏。现已改为恒定 `mode=initial`。

**查看位置**：`crawl-api.js` 第 551 行

---

### 3.4 排序默认值

待审批列表默认按 `added`（入池时间）降序，新入池的置顶：

```javascript
// admin.js 第 21 行
const S = {
  sort: 'added',    // ← 默认按入池时间
  sortDir: 'desc',  // ← 降序（最新在前）
  filter: 'all',    // ← 默认显示全部（不是 todo）
};
```

**已修复的 bug**：之前默认 `sort='date'`，新入池的会沉底；默认 `filter='todo'`，只显示待处理，已确认的看不到。

### 3.6 Git 代理配置（GitHub 直连不通）

本机没有直连 GitHub 的能力（443 超时），必须走代理：

```bash
# 检查是否已配
git config --local http.proxy
git config --local https.proxy

# 如果没配或代理端口变了，重配：

git config --local https.proxy http://127.0.0.1:7890
```

**换机器 / 代理端口变了要重配，否则 `git push` 会卡 21 秒后超时失败。**

推送前建议先 `git fetch` 看是否分叉，分叉用 `git pull --rebase` 保持线性历史。

### 3.7 杀 Windows 进程的命令陷阱

Git Bash 下 `taskkill /PID xxx /F` 会被路径转换破坏，杀进程一律用 PowerShell：

```powershell
# ✅ 正确

# ❌ 错误（会报"无效参数"）

```

### 3.8 MOCK_LOGIN 模式须知

`MOCK_LOGIN=true` 绕过飞书 OAuth，模拟身份「张伟」。

- **本地开发**：必须开启，否则 `/auth/login` 跳飞书但本地无回调地址
- **生产部署**：绝对不能开，`auth.js` 第 178 行有硬拦截

```javascript
// auth.js
if (IS_PROD && process.env.MOCK_LOGIN === 'true') {
  console.error('[auth][fatal] 生产环境禁止开启 MOCK_LOGIN');
  process.exit(1);
}
```

**Cookie 过期问题**：服务重启后浏览器 cookie 失效，前端会自动调 `/auth/login` 补登。如果补登失败，手动访问 `http://localhost:4201/auth/login` 触发一次即可。

## 四、核心业务规则（用户确认口径）

以下两条是用户 2026-09-10 明确确认的业务标准，**后续所有查询和开发都以这个为准**：

### 规则 1：今日增量 = 当天发布的政策

```javascript
// 判定逻辑（不要改口径）
const todayAdded = pendingQueue
  .filter(c => normalizePublishedDate(c.releaseDate || c.publishDate) === today)
  .length;
```

**不是**按入池时间统计。今天爬到但发布日是历史的，**不计入**今日增量。

### 规则 2：凡爬取入池的条目，必须进入待审批列表

一个都不能漏，不能因发布日旧而隐藏。

```javascript
// 前端调用的接口必须用 mode=initial（全量）
// 不要用 mode=daily，否则历史发布的新入池条目会被过滤掉
const resp = await fetch('/api/crawl/crawled-pending?mode=initial');
```

## 九、常见问题排查

### Q1：服务启动后 `/api/crawl/crawled-pending` 返回空？

**原因**：浏览器 session cookie 过期（服务重启后常见）。

**解决**：
1. 强制刷新页面（Ctrl+Shift+R）
2. 或手动访问 `http://localhost:4201/auth/login` 触发一次登录
3. 检查 `.env` 是否有 `MOCK_LOGIN=true`

### Q2：爬虫跑了但待审批列表不更新？

**原因**：`db.syncIfChanged()` 没被调用。

**解决**：在读取 `crawlQueue` / `crawlTasks` 的代码前加：
```javascript
const db = require('../../src/db');
db.syncIfChanged();
```

### Q3：今日增量恒为 0？

**原因**：用了错误的口径（按入池时间而非发布日期统计）。

**解决**：检查 `todayAdded` 的计算逻辑：
```javascript
// ✅ 正确
todayAdded = pendingQueue.filter(c => normalizePublishedDate(c.releaseDate) === today).length

// ❌ 错误（不要这样写）
todayAdded = pendingQueue.filter(c => shanghaiDate(c.createdAt) === today).length
```

### Q4：某个省份爬虫返回 SSL 错误？

**原因**：目标网站 SSL 证书配置问题（如山东、湖北）。

**解决**：这是服务端问题，不影响其他省份；已在 `sourceHealth` 中记录降级状态。如需修复，在 `crawler.js` 里对该源加 `httpsAgent` 跳过证书验证（仅调试用）。

### Q5：推送 Git 超时？

**原因**：代理未配置或端口变了。

**解决**：
```bash
git config --local http.proxy http://127.0.0.1:7890
git config --local https.proxy http://127.0.0.1:7890
```
