# 政策知识库自托管上线部署清单（P5）

> **操作细节见 [`生产部署手册.md`](./生产部署手册.md)**，本文件只作勾选清单。
> 部署前先跑 `node scripts/preflight.js`，它会自动体检本清单里 80% 的项目。

> 目标形态：自建服务器运行**统一网关**（`policy-api/src/server.js`：飞书 OAuth 登录 + 10 表只读 + 审核/订阅/采集写链路 + 自建前端托管，单进程单端口），前端为随包自建页面（总览首页 `/` + 审批工作台 `/admin/`），数据底座为飞书多维表格（读写均走 OpenAPI）。

## 0. 产物清单

| 产物 | 位置 | 说明 |
|---|---|---|
| 统一网关 | `policy-api/src/server.js` | 唯一运行入口（老 `src/server.js` 仅 OAuth 演示，不再使用） |
| 自建前端 | `policy-api/public/` | 随代码包托管：`index.html` 总览首页 + `app/` 资源 + `admin/` 审批工作台；可随时改版 |
| 本地数据 | `data/db.json` | 审核/订阅/采集队列/待同步 outbox，**必须挂 volume** |
| 反代示例 | `nginx.example.conf` | 443 → 本机端口，透传 Host/X-Forwarded-Proto |
| 容器 | `Dockerfile` | 已指向统一网关 + 自建前端 + data volume |
| 质检脚本 | `scripts/scan-quality.js` | 只读体检，可挂周任务 |

## 1. 服务器侧（自建主机 / 云主机）

- [ ] **1.1 域名与证书**：准备 `policy.yourdomain.com`，certbot 签发 Let's Encrypt（飞书回调强制 HTTPS）
- [ ] **1.2 反向代理**：按 `nginx.example.conf` 部署，`proxy_pass http://127.0.0.1:3000`；**必须透传 `Host` 与 `X-Forwarded-Proto`**（OAuth 回调地址按这些头拼接）
- [ ] **1.3 Node 20+ 或 Docker**（二选一）
  - 裸机：`git clone` 本仓库 → `npm install --omit=dev`
  - Docker：`docker build -t policy-kb . && docker run -d -v /srv/policy-kb/data:/app/data -p 3000:3000 policy-kb`
- [ ] **1.4 前端就位（随包自带，仅校验）**：`ls policy-api/public/index.html policy-api/public/admin/index.html`，两文件存在即 OK（无需任何平台构建产物）
- [ ] **1.5 环境变量**（`feishu-webapp/.env`，示例见下）
  ```ini
  FEISHU_APP_ID=cli_xxxx
  FEISHU_APP_SECRET=xxxx
  FEISHU_REDIRECT_URI=https://policy.yourdomain.com/auth/callback
  SESSION_SECRET=<openssl rand -hex 32>
  PORT=3000
  # 前端随代码包自托管（policy-api/public），无需 SPA_DIR
  # MOCK_LOGIN=true  ← 严禁在生产开启（会绕过登录）
  ```
- [ ] **1.6 进程守护**：systemd / pm2 / `docker restart=always`，开机自启
- [ ] **1.7 数据备份**：`data/db.json` 每日快照（crontab `cp db.json db.$(date +%F).json`，保留 30 天）；该文件含待同步写操作，丢失=丢写
- [ ] **1.8 健康检查**：`GET /healthz` 接入监控拨测
- [ ] **1.9 验收冒烟**：
  - `curl https://policy.yourdomain.com/healthz` → 200
  - 浏览器访问 `/` → 跳转 `/auth/login` → 飞书扫码 → 回到首页且右上角显示真实姓名
  - `/api/dashboard/stats` 登录后返回 `source=bitable`、578 条口径

## 2. 飞书开放平台后台配置

- [ ] **2.1 创建企业自建应用**：开发者后台 → 创建应用 → 记录 App ID / App Secret
- [ ] **2.2 添加网页应用能力**：应用能力 → 网页 → 桌面端主页 `https://policy.yourdomain.com/`，移动端主页同值
- [ ] **2.3 安全设置 → 重定向 URL**：登记 `https://policy.yourdomain.com/auth/callback`（与 `FEISHU_REDIRECT_URI` 完全一致，含协议大小写）
- [ ] **2.4 权限开通**（权限管理 → 开通以下 API 权限）：
  - `bitable:app`（多维表格，读；写链路需"可编辑"级别的表授权配合）
  - 获取登录用户信息（`authen:1`，用于 OAuth 换取 user_access_token / 用户身份）
- [ ] **2.5 多维表格授权**（写链路 403 的根因就在这一步）：
  - 打开政策知识库 Base → 右上「…」→ 更多 → 添加文档应用 → 搜索本应用 → 授予**可编辑**
  - 10 张专题表（最低工资/平均工资/公积金/年金/大病医疗/高温津贴/残疾职工/婚育相关/病假工资/薪酬月刊）随 Base 整体授权
  - 未授权时表现：读接口正常（应用有 bitable:app 只读权限）但 `确认入库` 等写操作降级进待同步队列（HTTP 201 + `pendingSync:true`），需要事后 `POST /api/bitable/sync-out` 补推
- [ ] **2.6 发布版本**：版本管理与发布 → 创建版本 → 申请线上可用范围（全员或指定部门）→ 发布
- [ ] **2.7 验收**：飞书工作台看到应用入口 → 打开即为登录态（免扫码，网页应用自动授权）→ 采集比对页点「确认入库」提示真实写入成功（而非待同步）

## 3. 上线后巡检（建议节奏）

| 频率 | 动作 |
|---|---|
| 每日 | `/healthz` 拨测 + db.json 备份 |
| 每周 | `node scripts/scan-quality.js`，对比上周 raw.json 的新增问题行 |
| 每月 | 检查 `data/db.json` 中 `syncOutbox` 是否积压（积压=表格写权限又失效） |

## 4. 已知风险与回退

- **MOCK_LOGIN**：生产环境绝不开启，否则任何访问者以模拟身份进入（服务启动日志会有红字警告）
- **SESSION_SECRET**：更换会使全部在线会话失效，属预期行为
- **Base 更换/迁移**：表 ID 变化需同步更新 `policy-api/src/policy-sources.js` 并重启
- **回退方案**：网关是无状态读 + 本地 db.json 单文件写，回滚=切回上一个镜像/tag；db.json 按日期备份可直接还原
